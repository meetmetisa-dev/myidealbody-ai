Privacy Policy

For the MyIdealBody AI development beta maintained through the meetmetisa-dev GitHub repository.

1. Scope and developer contact

This policy covers the public MyIdealBody AI GitHub Pages website and the signed Google Play Internal or Closed testing build produced from this repository when it uses DEMO_MODE=true. The beta is intended for adults, does not create user accounts, and is not yet a paid public service.

For a privacy inquiry, use the contact route on the meetmetisa-dev GitHub profile. For a security concern, follow the repository’s private security-reporting instructions. Do not post meal photos, health information, identifiers, or vulnerability details in a public issue.

2. Current beta behavior at a glance

  • The public website has no production API configured. A selected photo is previewed locally in the browser and is not uploaded. Its guided nutrition range comes from the meal, portion, and oil/sauce options the user selects—not from image recognition.
  • The Android beta defaults to DEMO_MODE. The selected camera or gallery photo stays on the device, and the app generates its fixed sample result entirely on-device without making an analysis network request.
  • The fixed Android demo result does not consume the scan allowance and cannot be saved to the diary.
  • The beta contains no advertising SDK, behavioral analytics SDK, or crash-reporting SDK, and it does not use meal photos for model training.
  • Nutrition results are estimates for general wellness, not medical measurements or advice.

4. Permissions and data not requested

  • Camera: used only when the user chooses camera capture. Live camera frames are sampled on-device for a simple brightness cue; audio is disabled.
  • Internet: present for optional external policy/support links and a separately configured non-demo analysis service. The default Android demo neither requests analysis nor initializes Play Billing.
  • Gallery: the Android system picker is used. The app does not request broad storage access or alter gallery originals. Android or the selected media provider may supply an app-readable temporary copy for the result flow.

The current beta does not request precise location, contacts, microphone access, advertising ID, or broad photo-library/storage permission. It has no sign-in flow and therefore does not intentionally collect a name, email address, or account password.

5. Purpose, sharing, and training

Local preferences and any non-demo diary data are used only to provide language selection, goals, daily limits, reviewable meal history, and settings. The bundled fixed result supports local testing of the scan/result flow and is not saved. The local demo does not initialize billing.

We do not sell or rent beta user data, serve behavioral advertising, or use selected meal photos to train models. Under the current defaults, no selected meal photo or demo-analysis request is shared with an analysis API. A future model provider is not authorized by this policy.

6. Retention and deletion

  • A website photo preview remains in browser memory until it is removed, replaced, or the page is closed. Guided inputs/results are not persisted by the website.
  • The website language preference remains in local storage until browser site data is cleared.
  • Android camera captures are temporary app files and are deleted after the result flow where the app can do so; Android may also evict cache files. A gallery picker or media provider may create an app-readable temporary copy that remains on-device until Android or the provider clears it, app data is cleared, or the app is uninstalled. The app does not intentionally copy a gallery image into the diary, and gallery originals are not changed or deleted.
  • Any non-demo Android diary entries remain on the device until the user uses Clear history, clears app data, or uninstalls. Calorie and protein goals remain until changed, app data is cleared, or the app is uninstalled. Recent successful non-demo scan timestamps are pruned to approximately two days. The fixed demo result is not added to the diary or scan history. Language, onboarding, and consent choices remain until changed or app data is cleared.

In the Android app, use Settings → Clear history to delete local diary entries. Use Android system settings to clear all app data. In a browser, clear site data for the GitHub Pages origin to remove the language preference.

7. Security and international processing

The release configuration blocks cleartext network traffic, Android backups are disabled, the Android demo analysis stays on-device, and the public website does not contain provider secrets. The optional backend validates upload size and type when separately configured. These controls reduce risk, but no development beta or network service can be guaranteed completely secure.

GitHub or Google may process technical data in countries other than the user’s. Because a production model provider and hosting region have not been selected, real-photo cross-border processing is not enabled or covered by this notice.

8. Required update before real photo analysis

The code contains an optional path that can send a photo to a separately configured HTTPS API. This path is not enabled on the current public website, and the Android default performs its fixed demo entirely on-device with no analysis request. Before enabling real-photo upload, the operator must update this policy and consent screen, identify every provider and subprocessor, verify data location and retention, define deletion and inquiry procedures, complete Google Play Data safety and Health Apps declarations, and obtain any required legal review.

9. Changes to this policy

Material changes will be posted on this page with a revised effective date. A change in this document alone does not enable production upload; the application configuration, in-app disclosure, and store declarations must also be updated consistently.

Kebijakan Privasi

Untuk beta pengembangan MyIdealBody AI yang dikelola melalui repositori GitHub meetmetisa-dev.

1. Cakupan dan kontak pengembang

Kebijakan ini berlaku untuk situs publik MyIdealBody AI di GitHub Pages dan build pengujian Internal atau Tertutup Google Play yang ditandatangani dari repositori ini saat menggunakan DEMO_MODE=true. Beta ditujukan bagi pengguna dewasa, belum membuat akun pengguna, dan belum menjadi layanan publik berbayar.

Untuk pertanyaan privasi, gunakan jalur kontak pada profil GitHub meetmetisa-dev. Untuk masalah keamanan, ikuti petunjuk pelaporan keamanan privat repositori. Jangan menuliskan foto makanan, informasi kesehatan, identitas, atau rincian kerentanan pada issue publik.

2. Ringkasan perilaku beta saat ini

  • Situs publik belum dikonfigurasi dengan API produksi. Foto yang dipilih hanya dipratinjau secara lokal di browser dan tidak diunggah. Rentang gizi terpandu berasal dari pilihan jenis makanan, porsi, dan minyak/saus—bukan dari pengenalan gambar.
  • Beta Android memakai DEMO_MODE secara bawaan. Foto kamera atau galeri tetap berada di perangkat, dan aplikasi menghasilkan contoh hasil tetap sepenuhnya di perangkat tanpa permintaan jaringan untuk analisis.
  • Hasil demo Android tetap tidak mengurangi batas pemindaian dan tidak dapat disimpan ke catatan makanan.
  • Beta tidak memuat SDK iklan, analitik perilaku, atau pelaporan crash, serta tidak menggunakan foto makanan untuk melatih model.
  • Hasil gizi adalah estimasi untuk kebugaran umum, bukan pengukuran atau saran medis.

4. Izin dan data yang tidak diminta

  • Kamera: digunakan hanya saat pengguna memilih pengambilan melalui kamera. Bingkai kamera langsung hanya disampel di perangkat untuk petunjuk sederhana mengenai pencahayaan; audio dinonaktifkan.
  • Internet: tersedia untuk tautan kebijakan/bantuan eksternal opsional dan layanan analisis non-demo yang dikonfigurasi terpisah. Demo Android bawaan tidak meminta analisis dan tidak menginisialisasi Play Billing.
  • Galeri: menggunakan pemilih sistem Android. Aplikasi tidak meminta akses penyimpanan luas dan tidak mengubah foto asli di galeri.

Beta saat ini tidak meminta lokasi presisi, kontak, akses mikrofon, advertising ID, atau izin luas untuk pustaka foto/penyimpanan. Belum ada proses masuk akun sehingga aplikasi tidak sengaja mengumpulkan nama, alamat email, atau kata sandi akun.

5. Tujuan, pembagian data, dan pelatihan model

Preferensi lokal dan catatan makanan non-demo jika ada hanya digunakan untuk pilihan bahasa, target, batas harian, riwayat makanan yang dapat diperiksa, dan pengaturan. Hasil tetap bawaan mendukung pengujian lokal alur pemindaian/hasil dan tidak disimpan. Demo lokal tidak menginisialisasi billing.

Kami tidak menjual atau menyewakan data pengguna beta, menampilkan iklan perilaku, atau memakai foto makanan yang dipilih untuk melatih model. Dengan pengaturan bawaan saat ini, tidak ada foto makanan pilihan atau permintaan analisis demo yang dibagikan dengan API analisis. Kebijakan ini tidak memberikan izin kepada penyedia model di masa depan.

6. Penyimpanan dan penghapusan

  • Pratinjau foto situs tetap berada dalam memori browser sampai dihapus, diganti, atau halaman ditutup. Pilihan dan hasil terpandu tidak disimpan oleh situs.
  • Preferensi bahasa situs tetap berada dalam penyimpanan lokal sampai data situs pada browser dihapus.
  • Foto kamera Android merupakan berkas sementara aplikasi dan dihapus setelah alur hasil jika dapat dilakukan aplikasi; Android juga dapat membersihkan cache. Foto asli dari galeri tidak diubah atau dihapus.
  • Catatan makanan non-demo jika ada tetap di perangkat sampai pengguna memilih Hapus riwayat, menghapus data aplikasi, atau mencopot aplikasi. Target kalori dan protein tetap tersimpan sampai diubah, data aplikasi dihapus, atau aplikasi dicopot. Waktu pemindaian non-demo berhasil terakhir dipangkas menjadi sekitar dua hari. Hasil demo tetap tidak ditambahkan ke catatan makanan atau riwayat pemindaian. Pilihan bahasa, onboarding, dan persetujuan tetap disimpan sampai diubah atau data aplikasi dihapus.

Di aplikasi Android, gunakan Pengaturan → Hapus riwayat untuk menghapus catatan makanan lokal. Gunakan pengaturan sistem Android untuk menghapus seluruh data aplikasi. Di browser, hapus data situs untuk origin GitHub Pages guna menghapus preferensi bahasa.

7. Keamanan dan pemrosesan lintas negara

Konfigurasi rilis menolak jaringan tanpa enkripsi, pencadangan Android dinonaktifkan, analisis demo Android tetap di perangkat, dan situs publik tidak memuat rahasia penyedia. Backend opsional memeriksa tipe dan ukuran unggahan jika dikonfigurasi terpisah. Kontrol ini mengurangi risiko, tetapi tidak ada beta pengembangan atau layanan jaringan yang dapat dijamin sepenuhnya aman.

GitHub atau Google dapat memproses data teknis di negara selain negara pengguna. Karena penyedia model dan wilayah hosting produksi belum dipilih, pemrosesan lintas negara untuk foto nyata belum diaktifkan dan belum dicakup oleh pemberitahuan ini.

8. Pembaruan wajib sebelum analisis foto nyata

Kode memuat jalur opsional yang dapat mengirim foto ke API HTTPS yang dikonfigurasi terpisah. Jalur ini tidak aktif pada situs publik saat ini, sedangkan pengaturan bawaan Android menjalankan demo tetap sepenuhnya di perangkat tanpa permintaan analisis. Sebelum unggahan foto nyata diaktifkan, operator wajib memperbarui kebijakan dan layar persetujuan, menyebutkan semua penyedia dan subprosesor, memverifikasi lokasi dan masa penyimpanan data, menetapkan prosedur penghapusan dan pertanyaan privasi, melengkapi deklarasi Data safety dan Health Apps Google Play, serta memperoleh tinjauan hukum yang diperlukan.

9. Perubahan kebijakan

Perubahan penting akan ditampilkan pada halaman ini dengan tanggal berlaku yang diperbarui. Perubahan dokumen saja tidak mengaktifkan unggahan produksi; konfigurasi aplikasi, pemberitahuan dalam aplikasi, dan deklarasi toko juga harus diperbarui secara konsisten.
